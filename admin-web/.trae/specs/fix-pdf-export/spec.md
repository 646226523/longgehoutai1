# 修复导出PDF/打印按钮无反应问题

## 问题描述

检测报告详情抽屉顶部的「打印」和「导出PDF」按钮点击后毫无反应。

**根因分析（代码审查发现）：**

1. **变量名错误（主要原因）**：`handlePrint` 函数内使用了 `message.error(...)`，但组件中正确的变量名是 `msg`（第451行：`const { message: msg } = App.useApp();`）。当浏览器弹窗拦截器阻止 `window.open()` 时，`message.error()` 抛出 `ReferenceError`，函数静默失败。

2. **弹窗被拦截**：`window.open('', '_blank', ...)` 在现代浏览器中常被弹窗拦截器阻止，导致 `printWindow` 为 `null`。

3. **错误处理失效**：即使弹窗被拦截，由于变量名错误，用户看不到任何错误提示。

## 用户

管理员，需要从检测报告详情中打印或导出PDF。

## 目标

1. 「打印」按钮点击后，能正常触发浏览器打印功能
2. 「导出PDF」按钮点击后，能打开打印对话框，用户可选择"另存为PDF"导出
3. 打印/导出时，仅显示报告内容
4. **稳健性**：不依赖 `window.open`，避免被弹窗拦截器阻止
5. **正确的错误提示**：当操作失败时给用户明确反馈

## 非目标

- 不引入额外的PDF生成库（如 jspdf、html2canvas）
- 不实现真正的服务端PDF生成
- 不修改报告数据本身

## 功能需求

### FR-1: 打印功能
- 点击「打印」按钮，浏览器弹出打印对话框
- 打印预览中仅显示报告详情内容（报告头、检测对象、检测结果等）
- 不显示侧边栏、导航菜单、按钮等UI元素
- 使用 `window.print()` 在当前页面触发打印（而非新窗口）

### FR-2: 导出PDF功能
- 点击「导出PDF」按钮，浏览器弹出打印对话框
- 用户选择"另存为PDF"后，将报告保存为PDF文件
- 打印内容与打印按钮一致

### FR-3: 打印样式
- 打印时使用 `@media print` CSS 样式控制布局
- 通过 CSS class 显隐控制，仅展示报告内容
- 保留报告的核心样式（渐变标题、卡片、统计数据等）
- 合理分页，避免卡片在中间被截断

### FR-4: 错误处理
- 当打印/PDF导出失败时，给用户明确的错误提示
- 所有错误提示使用正确的 `msg` 变量（而非未定义的 `message`）

## 非功能需求

- **兼容性**：在 Chrome/Edge 等主流浏览器上正常工作
- **响应速度**：点击按钮后 500ms 内弹出打印对话框
- **可靠性**：不因报告内容长短而失败
- **不依赖弹窗**：使用 `window.print()` 直接在当前页面触发

## 约束

- 项目目前无 PDF 生成库，使用浏览器原生打印功能
- 需与现有 Ant Design 5 组件体系兼容
- 修复需保持现有报告打印内容的完整性
