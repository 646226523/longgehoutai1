# 赛鸽基因溯源平台 - 后台管理系统架构 Spec

## Why
前端移动端 H5 应用「龙鸽基因 - 赛鸽基因全链路溯源」已面向 C 端用户提供基因查询、NFT 资产、赛事核验、公棚入驻、检测预约、会员特权等核心能力,但缺少统一的 B 端后台运营平台来支撑数据维护、业务审核、资产上链、纠纷仲裁与内容运营。需要设计一套覆盖全业务链路的后台管理架构,实现「前端展示 — 后台管控 — 数据闭环」的完整运营体系。

## What Changes
- **新增** 后台管理系统整体架构(独立 B 端管理系统,与现有 C 端 H5 分离部署)
- **新增** 9 大业务管理模块 + 数据统计中心 + 系统管理基础模块
- **新增** 基于 RBAC 的角色权限模型(超级管理员 / 运营管理员 / 审核员 / 赛事专员 / 检测机构 / 仲裁员 / 内容运营)
- **新增** 前后端技术架构规范与目录结构约定
- **新增** 各业务模块数据流转与关联关系定义

## Impact
- Affected specs: 新建后台管理系统架构(独立 spec)
- Affected code: 新建独立后台管理系统项目(`admin-web` 前端 + `admin-api` 后端),与现有 C 端 H5(`p:\龙鸽项目\longgehoutai`)解耦,通过共享业务数据库与 API 层协同

---

## 系统总体架构

### 技术架构
- **前端** `admin-web`:React 18 + Ant Design Pro 5 + Vite + TypeScript,响应式 PC 后台布局(侧边栏 + 顶栏 + 内容区 + 面包屑)
- **后端** `admin-api`:Node.js(Express/Nest.js),RESTful API,JWT 鉴权,与 C 端共享业务数据库
- **数据层**:与 C 端共享业务数据库(MySQL/PostgreSQL),新增 `admin_user`、`role`、`permission`、`audit_log` 等后台专属表
- **基础设施**:对象存储(图片/凭证)、区块链节点(NFT 上链对接)、消息队列(异步上链/通知)
- **部署**:前后端分离部署,后台仅内网/VPN 可访问

### 角色权限模型(RBAC)
| 角色 | 职责范围 |
|---|---|
| 超级管理员 | 全部权限、系统配置、管理员与角色管理 |
| 运营管理员 | 内容运营、Banner/资讯/公告、数据查看 |
| 审核员 | 基因录入审核、公棚入驻审核、NFT 上链审核 |
| 赛事专员 | 赛事创建发布、成绩录入、赛事核验 |
| 检测机构 | 检测预约处理、检测报告录入 |
| 仲裁员 | 交易纠纷仲裁、证据审核、裁决执行 |
| 内容运营 | 首页内容、资讯、会员权益配置 |

## ADDED Requirements

### Requirement: 后台登录与会话
系统 SHALL 提供管理员账号密码登录,登录后下发 JWT Token,所有后台接口需校验 Token 与对应模块权限。

#### Scenario: 管理员登录
- **WHEN** 管理员使用账号密码登录
- **THEN** 校验通过后下发 Token,记录登录日志,跳转工作台首页

#### Scenario: 越权访问
- **WHEN** 无权限用户访问受限模块或接口
- **THEN** 返回 403,前端隐藏对应菜单与按钮

### Requirement: 基因信息管理模块
系统 SHALL 提供赛鸽基因档案的全链路管理,支撑前端「基因查询」「基因库」「手动录入」功能。

包含子能力:
- 基因档案管理(鸽只基本信息、血统、基因序列数据、溯源二维码)
- 基因检测记录管理(对接检测机构、报告关联)
- 手动录入审核(C 端提交的手动录入数据审核入库)
- 溯源链路管理(鸽只繁育链路、血统树可视化)

#### Scenario: 手动录入审核
- **WHEN** 审核员打开手动录入待审列表
- **THEN** 可查看提交详情,通过后写入正式基因档案并生成溯源二维码;驳回时填写驳回理由,通知提交者

#### Scenario: 基因档案查询
- **WHEN** 管理员按足环号/鸽主/血统检索
- **THEN** 返回档案详情及关联的检测报告、赛事成绩、NFT 资产

### Requirement: NFT 资产管理模块
系统 SHALL 管理赛鸽 NFT 资产的铸造、上链、流转,支撑前端「NFT 资产」「资产链」功能。

包含子能力:
- NFT 铸造与上链管理(鸽只资产数字化、元数据管理、上链任务队列)
- 上链审核(审核通过后调用链上合约铸造)
- 资产流转记录(转让、交易记录追溯)
- 链上状态监控(铸造状态、合约地址、交易哈希)

#### Scenario: NFT 上链审核
- **WHEN** 审核员审核待上链资产
- **THEN** 通过后任务进入上链队列,异步调用链上合约铸造,完成后回写交易哈希与合约地址;失败自动重试并告警

### Requirement: 赛事管理模块
系统 SHALL 管理赛事全流程,支撑前端「赛事通」「赛事核验」「赛事详情」功能。

包含子能力:
- 赛事创建与发布(赛事信息、规程、参赛范围、时间节点)
- 赛事核验(参赛鸽只资格核验、足环与基因档案比对)
- 成绩录入与管理(比赛成绩、排名、空距、分速)
- 赛事状态管理(报名中、集鸽中、比赛中、已结束、已归档)

#### Scenario: 赛事核验
- **WHEN** 赛事专员对参赛鸽进行资格核验
- **THEN** 系统比对足环号与基因档案,核验通过后该鸽计入参赛名单;不通过标记原因

### Requirement: 公棚管理模块
系统 SHALL 管理公棚入驻与鸽棚信息,支撑前端「公棚入驻」功能。

包含子能力:
- 公棚入驻申请审核(资质材料、场地证明审核)
- 公棚信息管理(公棚档案、容量、负责人、地理位置)
- 鸽棚管理(棚内鸽只登记、存棚状态、入棚/出棚记录)

#### Scenario: 公棚入驻审核
- **WHEN** 审核员审核公棚入驻申请
- **THEN** 查看资质材料与场地证明,通过后公棚正式入驻并开通管理后台子账号

### Requirement: 检测预约管理模块
系统 SHALL 管理基因检测预约与报告,支撑前端「检测预约」功能。

包含子能力:
- 预约订单管理(预约状态、排期、取消/改期)
- 检测机构管理(机构资质、对接状态、检测项目与报价)
- 检测排期(检测机构产能日历、自动排期)
- 检测报告管理(报告录入、关联鸽只基因档案)

#### Scenario: 预约排期
- **WHEN** 用户在 C 端提交检测预约
- **THEN** 后台生成预约订单,运营/检测机构确认排期,完成后通知用户

### Requirement: 拍卖管理模块
系统 SHALL 管理赛鸽拍卖场次与竞拍,支撑赛鸽资产流转交易。

包含子能力:
- 拍卖场次管理(场次创建、起止时间、起拍价、加价幅度)
- 拍品管理(拍品上架、关联鸽只/NFT 资产、拍品图文)
- 竞价记录(实时竞价、出价历史)
- 成交管理(成交确认、付款状态、交割流程)

#### Scenario: 拍卖成交
- **WHEN** 拍卖场次结束
- **THEN** 系统按最高出价判定成交,生成成交单,通知买卖双方进入交割流程

### Requirement: 仲裁管理模块
系统 SHALL 处理交易纠纷仲裁,保障交易双方权益。

包含子能力:
- 仲裁案件管理(案件受理、立案、审理状态)
- 证据材料管理(双方举证、凭证存档)
- 仲裁结果(裁决、退款/交割执行)
- 仲裁记录归档

#### Scenario: 纠纷立案
- **WHEN** 交易一方发起纠纷申诉
- **THEN** 后台生成仲裁案件,仲裁员审理证据后作出裁决,执行退款或强制交割

### Requirement: 用户与会员体系模块
系统 SHALL 管理 C 端用户账号与会员体系,支撑前端「我的」「会员等级」「会员特权」功能。

包含子能力:
- 用户管理(账号信息、实名认证、状态封禁/解封)
- 会员等级管理(等级规则、成长值、升降级配置)
- 会员权益配置(等级对应权益、特权发放)
- 用户认证管理(实名、鸽主认证、公棚认证)

#### Scenario: 会员等级配置
- **WHEN** 运营调整会员等级规则
- **THEN** 修改成长值门槛与对应权益,变更后按新规则重新计算用户等级

### Requirement: 内容运营管理模块
系统 SHALL 管理首页与内容展示,支撑前端首页 Banner、资讯、公告、数据统计展示。

包含子能力:
- Banner 管理(图片、跳转链接、排序、上下架)
- 资讯管理(文章发布、分类、置顶)
- 公告管理(系统公告、推送通知)
- 首页数据统计展示配置(展示指标、数据源)

#### Scenario: 资讯发布
- **WHEN** 运营发布资讯文章
- **THEN** 富文本编辑后发布,C 端资讯模块即时展示

### Requirement: 数据统计中心
系统 SHALL 提供全局数据统计与可视化,辅助运营决策。

包含子能力:
- 基因数据统计(档案总量、检测量、溯源查询量)
- 赛事数据统计(赛事场次、参赛鸽数、完赛率)
- 交易数据统计(NFT 铸造量、拍卖成交量、交易额趋势)
- 用户数据统计(注册量、活跃、会员分布)
- 数据看板(关键指标卡片、趋势折线图、排行榜)

#### Scenario: 数据看板
- **WHEN** 管理员进入数据统计中心
- **THEN** 展示各维度关键指标卡片与趋势图表,支持时间范围筛选

### Requirement: 系统管理模块
系统 SHALL 提供后台基础管理能力。

包含子能力:
- 管理员管理(账号增删改、状态)
- 角色管理(角色定义、权限分配)
- 权限管理(菜单权限、按钮权限、数据权限)
- 操作日志(管理员操作审计日志)
- 系统配置(参数配置、字典管理)

#### Scenario: 角色权限分配
- **WHEN** 超管为角色分配权限
- **THEN** 勾选菜单与按钮权限,保存后该角色管理员即时生效

## 模块间数据流转关系

```
基因信息管理 ──(鸽只档案)──┬──> NFT 资产管理 ──(资产)──> 拍卖管理 ──(成交)──> 仲裁管理
                           │                              │
                           ├──> 赛事管理 ──(成绩)──────────┘
                           │
公棚管理 ──(鸽棚/鸽只)──────┘
检测预约管理 ──(检测报告)──> 基因信息管理
用户与会员体系 ──(用户)──> 所有业务模块(归属)
内容运营管理 ──(首页内容)──> C 端展示
数据统计中心 <-(汇总)── 所有业务模块
系统管理 <-(审计)── 所有后台操作
```

```
      auction/              # 拍卖管理
      arbitration/          # 仲裁管理
      user-member/          # 用户与会员体系
      content/              # 内容运营管理
      statistics/           # 数据统计中心
      system/               # 系统管理
    services/               # API 调用
    access/                 # 权限控制

  src/
    modules/                # 业务模块(对应上述各模块)
    middlewares/            # 鉴权、权限、日志
    models/                 # 数据模型
    routes/                 # 路由
```
