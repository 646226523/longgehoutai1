# 赛事管理 - 地图选点与赛线规划功能 PRD

## 概述
- **摘要**: 将现有"新增赛事"从简单的信息录入表单升级为赛线规划工具，核心增加地图选点、空距自动计算、赛线可视化三大能力，解决当前手动输入地址/空距导致的数据不准确、效率低下、无法预览赛线合理性的问题。
- **目的**: 让管理员通过地图点选司放地和归巢地，系统自动计算空距并在地图上展示完整赛线，将赛事创建从"填表"升级为"规划赛线"。
- **目标用户**: 后台赛事管理员，负责创建和管理信鸽赛事的工作人员。

## 目标
- 提供地图选点功能，替代手动输入地址，支持搜索选点、地图点击、拖拽微调三种方式
- 实现起点→终点自动空距计算（Haversine公式），支持中途点累加
- 地图可视化赛线，展示起点→中途点→终点的路线连线
- 响应式适配（2560×1440 / 1920×1200 / 1920×1080）
- 后端数据库扩展经纬度字段，支持存储地理坐标数据
- 保持与现有赛事列表、核验、成绩等功能的兼容性

## 非目标（不在范围内）
- 支持地图 SDK 容器化渲染，显示接近真实地图的周边底图效果，优先复用现有页面已有的地图渲染方式
- 不实现真实的高德/百度地图 API 调用（避免 API Key 管理和网络依赖）
- 不实现真实的反向地理编码服务
- 不实现 3D 赛事追踪功能（预留 GeoJSON 数据结构即可）
- 不实现海拔剖面分析（仅展示途经城市和预计飞行时间）
- 不以“地区文本 + 手工空距”作为最终交互方式；这些字段仅作为兼容回退或历史数据展示

## 背景与上下文
- 当前赛事表（competitions）仅有 `location TEXT` 和 `distance REAL` 字段，缺少起点/终点经纬度
- 现有"新增赛事"弹窗为 640px 宽的 ModalForm，包含：赛事名称、类型、主办方、比赛地点、空距、开始时间、结束时间、赛事规程
- 赛事列表页使用 ProTable + ModalForm 模式，弹窗宽度限制导致无法展示地图
- 空距字段需手动输入，容易出现人为误差
- 比赛地点为纯文本，无法验证地址准确性
- 项目现有依赖：React 18、Ant Design 5、@ant-design/pro-components、dayjs、echarts
- 当前实现已扩展为左表单右地图页面，并保留历史字段回填与编辑兼容

## 功能需求
- **FR-1**: 起点（司放地）地图选点 - 支持搜索选点、地图点击标记、拖拽微调，自动回填经纬度和地址
- **FR-2**: 终点（归巢地）地图选点 - 同起点，独立操作
- **FR-3**: 空距自动计算 - 起点→中途点→终点累加计算，使用 Haversine 公式
- **FR-4**: 中途点管理 - 支持添加/删除/排序中途点，添加后空距自动重算
- **FR-5**: 赛线地图可视化 - 地图上显示起点→中途点→终点的路线折线，并呈现周边底图/地理信息
- **FR-6**: 赛线分析面板 - 展示总空距、预计飞行时间、途经城市
- **FR-7**: 空距手动微调 - 自动计算后允许人工微调覆盖
- **FR-8**: 响应式布局 - 大屏左右分栏（表单+地图），小屏上下结构
- **FR-9**: 数据持久化 - 后端扩展数据库字段存储起点经纬度、终点经纬度、中途点 GeoJSON
- **FR-10**: 异常处理 - 起点终点相同、坐标超限、计算异常等场景的友好提示
- **FR-11**: 编辑回填 - 已存在赛事应能回填起点、终点、中途点、空距及赛线信息，并允许继续编辑
- **FR-12**: 提交链路稳定性 - 保存/更新赛事时不得再出现与赛事创建无关的 404 请求
- **FR-13**: 地图 SDK 容器渲染 - main 赛线地图区域应显示周边地图信息，避免空白容器或仅占位框
- **FR-14**: AntD Card 警告修复 - 页面内所有 `Card` 使用 `styles.body` 替代 `bodyStyle`

## 非功能需求
- **NFR-1**: 空距计算精度 ≤ 0.5%（与标准 Haversine 公式对比）
- **NFR-2**: 地图交互流畅，选点/拖拽响应时间 < 100ms
- **NFR-3**: 页面首屏加载时间 < 2s（地图使用内置 SVG，无网络请求）
- **NFR-4**: 支持 2560×1440、1920×1200、1920×1080 三种分辨率
- **NFR-5**: TypeScript 类型安全，编译零错误
- **NFR-6**: 与现有赛事列表、核验、成绩模块完全兼容
- **NFR-7**: 表单提交后页面应能稳定返回列表并刷新数据，不出现持续性 404 提示

## 约束
- **技术**: 不引入外部地图 SDK（无 API Key、无网络依赖），使用内置 SVG 中国地图 + 预置主要城市坐标数据
- **技术**: 前端框架为 React 18 + Ant Design 5 + TypeScript + Vite
- **技术**: 后端为 Express + SQLite，数据库扩展需兼容现有数据
- **业务**: 必须保留现有赛事列表页面的功能完整性
- **依赖**: 仅使用现有依赖（antd、@ant-design/pro-components、dayjs）

## 假设
- 用户无需真实地图服务，内置中国主要城市坐标 + SVG 地图足以满足选点需求
- 管理员已知晓司放地和归巢地的大致地理位置
- 空距精度到 0.01km 已满足信鸽比赛需求
- 中途点数量通常 ≤ 5 个
- 现有赛事数据的 location/distance 字段需保持向后兼容
- 目前页面中展示的 1230.0 空距如果来自历史/手工覆盖值，应允许通过回填逻辑继续保留，直到管理员重新选择赛线

## 验收标准

### AC-1: 地图选点功能
- **Given**: 管理员打开"新增赛事"页面
- **When**: 在起点选点区域输入"北京"并选择匹配项
- **Then**: 地图标记定位到北京，自动回填经度 116.4074、纬度 39.9043、地址"北京市"
- **验证**: `programmatic`

### AC-2: 空距自动计算
- **Given**: 起点已选为内江（105.0588, 29.5802），终点已选为北京（116.3974, 39.9087）
- **When**: 两个点都选定后
- **Then**: 空距自动计算约为 1230km（误差 ≤ 0.5%），显示在空距字段
- **验证**: `programmatic`

### AC-3: 赛线可视化
- **Given**: 起点和终点已选定
- **When**: 查看地图区域
- **Then**: 地图上显示起点（绿色标记）→ 终点（红色标记）的连线，起点终点标签正确
- **验证**: `human-judgment`

### AC-4: 中途点添加
- **Given**: 起点和终点已选定
- **When**: 点击"+ 添加中途点"并在地图上点击位置
- **Then**: 新增中途点标记，空距自动重算，路线折线经过中途点
- **验证**: `programmatic`

### AC-5: 数据库扩展
- **Given**: 后端数据库
- **When**: 迁移完成
- **Then**: competitions 表新增 start_lng、start_lat、start_address、end_lng、end_lat、end_address、waypoints、route_geojson 字段
- **验证**: `programmatic`

### AC-6: 响应式布局
- **Given**: 不同分辨率设备
- **When**: 2560×1440 下显示左右分栏（5:5），1920×1080 下显示上下结构
- **Then**: 地图始终完整展示，表单无溢出
- **验证**: `human-judgment`

### AC-7: 数据保存
- **Given**: 已填完赛事信息并选好起点终点
- **When**: 点击"确认发布"
- **Then**: 后端正确保存所有字段（含经纬度、中途点 GeoJSON），页面跳转回列表
- **验证**: `programmatic`

### AC-8: 异常处理
- **Given**: 起点与终点坐标相同
- **When**: 尝试保存
- **Then**: 前端提示"起点与终点不能相同"，阻止提交
- **验证**: `programmatic`
