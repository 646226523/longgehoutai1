# 修复新增基因档案后列表无数据 BUG - 产品需求文档

## 概述
- **摘要**: 修复赛鸽基因溯源平台后台管理系统中"新增基因档案"功能的严重BUG——用户填写完毕表单并点击确定按钮后，系统提示"新增成功"，但刷新页面后基因档案列表显示"暂无数据"，无法看到刚创建的档案记录。
- **目的**: 确保基因档案的创建功能完整可用，数据能够正确保存到后端数据库并在列表中正确显示。
- **目标用户**: 后台管理员、基因档案录入人员

## 目标
- [主要目标] 确保新增基因档案后，数据正确保存并在列表中显示
- [主要目标] 验证整个数据流：表单提交 → API请求 → 数据库存储 → 列表查询 → 前端展示
- [次要目标] 优化表单验证逻辑，确保手动输入鸽主信息时能正确触发验证和提交
- [次要目标] 确保 mock 插件和 Vite 代理配置正确工作，API 请求能正确转发到后端

## 非目标 (范围外)
- 不修改基因档案的字段结构
- 不修改列表的排序、筛选等功能
- 不添加新的业务功能
- 不修改检测报告、拍卖等其他模块的功能

## 背景与上下文
- 技术栈：前端 React + TypeScript + Vite + Ant Design，后端 Express + SQLite
- 架构：前后端分离，前端开发服务器(port 3014) + 后端 API 服务器(port 3015)
- 当前状态：
  1. 前端表单组件 `GeneForm.tsx` 中的 `handleSubmit` 函数验证逻辑可能存在问题
  2. `SearchSelect.tsx` 组件在 `allowCreate` 模式下使用 tags 模式处理鸽主选择
  3. mock 插件 `mock-plugin.js` 已将 `/api/gene` 添加到 skip 列表
  4. Vite 配置 `vite.config.js` 已配置 `/api/gene` 代理到后端 3015 端口
  5. 后端 `gene.ts` 路由的 POST `/api/gene/profiles` 和 GET `/api/gene/profiles` 接口实现完整
- 关键发现：
  - `List.tsx` 中 `handleFormSubmit` 调用 `createGeneProfile(payload)` 后显示"新增成功"提示
  - 但 `handleRefresh()` 刷新列表时调用 `getGeneProfiles()` 返回空数据
  - 可能的原因包括：表单验证被拦截、API 请求未正确发送、后端数据未正确保存、列表查询逻辑问题

## 功能需求
- **FR-1**: 当用户填写基因档案表单并点击"确定"按钮时，系统应正确验证所有必填字段
- **FR-2**: 表单验证通过后，系统应发送 POST `/api/gene/profiles` 请求创建新档案
- **FR-3**: 后端应正确保存档案数据到数据库
- **FR-4**: 创建成功后，系统应刷新列表并显示新创建的档案记录
- **FR-5**: 当用户手动输入鸽主姓名时，系统应正确处理并保存该鸽主信息
- **FR-6**: 当用户从现有鸽主列表中选择时，系统应自动填充鸽主电话并禁用该字段

## 非功能需求
- **NFR-1**: 表单提交响应时间 < 2秒
- **NFR-2**: API 请求成功率 > 99%
- **NFR-3**: 列表数据刷新延迟 < 1秒
- **NFR-4**: 错误提示信息清晰明确，能引导用户修正

## 约束
- **技术**: 
  - 前端必须使用现有的 React + TypeScript + Ant Design 技术栈
  - 后端必须使用现有的 Express + better-sqlite3 技术栈
  - 数据库为 SQLite，数据文件位于 `admin-api/data/admin.db`
- **业务**:
  - 基因档案的足环号必须符合格式 `CN-XXXX-XX-XXXXXX`
  - 足环号不可重复
  - 鸽主姓名为必填项
- **依赖**:
  - 前端开发服务器 (port 3014) 必须正常运行
  - 后端 API 服务器 (port 3015) 必须正常运行
  - 数据库文件 `admin-api/data/admin.db` 必须存在且可读写

## 假设
- [假设] 后端 API 服务器已正确启动并监听 3015 端口
- [假设] 数据库表 `gene_profiles` 已正确创建
- [假设] 用户具有 `gene:edit` 权限
- [假设] 前端代理配置正确，API 请求能转发到后端

## 验收标准

### AC-1: 表单验证正确
- **Given**: 用户打开新增基因档案表单
- **When**: 用户未填写必填字段（足环号、鸽名、鸽主）就点击"确定"
- **Then**: 系统显示"请检查表单必填项"警告，并标记错误字段
- **验证**: `programmatic`
- **备注**: 检查 `handleSubmit` 函数中的验证逻辑

### AC-2: 表单提交成功
- **Given**: 用户填写了所有必填字段（足环号、鸽名、鸽主）
- **When**: 用户点击"确定"按钮
- **Then**: 系统发送 POST `/api/gene/profiles` 请求，返回成功响应 `{ id: number }`
- **验证**: `programmatic`
- **备注**: 通过浏览器开发者工具或后端日志验证

### AC-3: 数据正确保存到数据库
- **Given**: API 请求返回成功
- **When**: 检查数据库中的 `gene_profiles` 表
- **Then**: 新创建的档案记录存在，且所有字段值正确
- **验证**: `programmatic`
- **备注**: 通过 SQL 查询数据库验证

### AC-4: 列表正确显示新档案
- **Given**: 档案已成功创建
- **When**: 系统刷新列表（用户点击"确定"后自动刷新，或手动刷新）
- **Then**: 基因档案列表显示新创建的档案记录，包含正确的足环号、鸽名、鸽主等信息
- **验证**: `programmatic`

### AC-5: 手动输入鸽主信息正常工作
- **Given**: 用户在鸽主姓名字段中手动输入新的鸽主名称
- **When**: 用户点击"确定"提交表单
- **Then**: 系统正确保存新鸽主名称和用户输入的鸽主电话
- **验证**: `programmatic`
- **备注**: 检查 `SearchSelect` 组件的 `allowCreate` 模式处理

### AC-6: 选择现有鸽主正常工作
- **Given**: 用户从鸽主下拉列表中选择一个现有鸽主
- **When**: 用户检查鸽主电话字段
- **Then**: 鸽主电话自动填充，且字段变为禁用状态
- **验证**: `human-judgment`
