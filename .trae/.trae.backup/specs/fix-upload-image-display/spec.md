# 修复图片上传后无法显示问题 - 产品需求文档

## 概述
- **摘要**: 修复赛鸽基因溯源平台中图片上传功能的BUG。当前前端上传图片后返回的是mock路径（如`/uploads/mock_xxx.jpg`），而非真实保存在服务器上的文件，导致图片无法正常显示。需要禁用上传接口的mock拦截，改为使用后端真实的上传服务。
- **目的**: 确保用户上传的鸽只照片等图片能够真实保存到服务器，并在页面中正确显示。
- **目标用户**: 后台管理员，需要上传鸽只照片、检测报告等图片文件。

## 目标
- 确保图片上传后能真实保存到后端服务器
- 确保上传的图片能够在前端正确显示
- 保持与现有上传组件的兼容性

## 非目标（范围外）
- 不修改图片上传的前端组件逻辑
- 不修改后端上传接口的实现
- 不添加图片压缩或水印等功能

## 背景与上下文
- **技术栈**: 前端 React + Vite，后端 Express + TypeScript
- **问题根源**: Vite开发服务器的mock插件拦截了`/api/upload`请求，返回了假的文件路径，没有真正将文件保存到磁盘
- **现有实现**: 
  - 后端已有完整的上传接口(`/api/upload`)，支持base64图片上传并保存到`uploads`目录
  - 后端已配置静态文件服务`/uploads`路径映射到`uploads`目录
  - Vite代理已配置`/api/upload`转发到后端
  - 但mock插件在代理之前拦截了请求，导致真实上传逻辑未被执行

## 功能需求
- **FR-1**: 禁用mock-plugin.js中对`/api/upload`的mock拦截，让请求通过代理转发到后端
- **FR-2**: 确保`/uploads`路径的静态资源请求也能正确转发到后端（用于显示已上传的图片）

## 非功能需求
- **NFR-1**: 上传接口响应时间应小于3秒
- **NFR-2**: 支持JPG、PNG、WEBP格式图片上传
- **NFR-3**: 单文件最大5MB

## 约束
- **技术**: 必须保持与现有上传组件的API兼容（base64格式上传）
- **依赖**: 依赖后端服务器正常运行

## 假设
- 假设后端上传服务正常运行在3015端口
- 假设uploads目录有写入权限
- 假设前端和后端的上传接口协议一致

## 验收标准

### AC-1: 图片上传成功
- **给定**: 用户在基因档案表单中点击上传图片按钮
- **当**: 用户选择一张图片并确认上传
- **那么**: 系统显示上传成功，返回的URL能真实访问到图片文件
- **验证**: `programmatic`

### AC-2: 图片在表单中正确显示
- **给定**: 用户已成功上传图片
- **当**: 系统预览或保存已上传的图片
- **那么**: 图片能够正常显示，不是空白或裂图
- **验证**: `programmatic`

### AC-3: 图片在列表页正确显示
- **给定**: 用户已保存带有图片的基因档案
- **当**: 用户查看基因档案列表
- **那么**: 列表中的鸽只照片能够正常显示
- **验证**: `programmatic`
