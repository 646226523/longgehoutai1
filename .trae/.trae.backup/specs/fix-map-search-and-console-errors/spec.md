# 地图搜索功能修复 & 控制台警告消除

## 问题描述

用户在「检测机构管理 → 新增/编辑机构」页面的地图选点区域，输入地址后点击「搜索」按钮没有任何反应，地图上不会出现定位标记。同时控制台存在 2 条 Ant Design 弃用警告。

## 根因分析

| # | 问题 | 严重度 | 影响 |
|---|------|--------|------|
| 1 | 搜索返回坐标双重 GCJ-02 转换（GCJ-02→WGS-84→GCJ-02） | 🔴 根因 | 标记位置偏移数百米，看起来像"没反应" |
| 2 | 高德 Geocoder 异步加载竞态，未就绪时搜索静默失败 | 🔴 严重 | 搜索可能无任何反馈 |
| 3 | 百度搜索同样存在 Geocoder 竞态问题 | 🔴 严重 | 同上 |
| 4 | 搜索空值无用户反馈 | 🟡 中等 | 用户以为"没反应" |
| 5 | Drawer `bodyStyle` 弃用警告 | 🟢 低 | 控制台报错 |
| 6 | Input `addonAfter` 弃用警告 | 🟢 低 | 控制台报错 |

## 目标用户

- 系统管理员：在新增/编辑检测机构时需要通过地址搜索快速定位机构位置

## 修复目标

1. 修复高德/腾讯/百度三大地图服务商的搜索功能，确保搜索后地图正确定位并显示标记
2. 消除控制台所有 Ant Design 弃用警告
3. 搜索空值时给予用户明确反馈
4. 统一使用 `useCallback` 保证闭包稳定性

## 非目标

- 不修改地图 SDK 加载逻辑
- 不修改数据库 schema
- 不添加新的地图服务商

## 约束与依赖

- 项目使用 React + TypeScript + Ant Design
- 坐标系统约定：数据库存储 WGS-84，地图渲染使用 GCJ-02（高德/腾讯）或 BD-09（百度）
- 现有坐标转换工具 `utils/coordinate-transform.ts` 已就绪

## 验收标准

### AC-1: 地址搜索正确定位 (rule)
- 在高德地图搜索框输入"天安门"并点击搜索，地图在正确位置显示标记点，偏差不超过 50 米
- 在腾讯地图搜索框输入相同地址，同样正确定位
- 在百度地图搜索框输入相同地址，同样正确定位

### AC-2: 搜索空值反馈 (rule)
- 搜索框为空时点击搜索按钮，显示"请输入搜索地址"提示

### AC-3: 控制台零弃用警告 (rule)
- 打开「新增检测机构」抽屉后，控制台不再出现 `bodyStyle` 弃用警告
- 打开「新增检测机构」抽屉后，控制台不再出现 `addonAfter` 弃用警告

### AC-4: TypeScript 编译无错误 (rule)
- `npx tsc --noEmit` 编译通过

### AC-5: 地图选点双向同步 (rule)
- 点击地图选点 → 正确触发 onChange 回调
- 搜索地址定位 → 正确触发 onChange 回调
- 两种方式获取的坐标精度一致（WGS-84 存储）
